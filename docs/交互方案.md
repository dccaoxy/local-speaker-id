# 交互方案：本地网页 + 一簇一卡

> 配套 `应用架构方案.md` D10–D13。唯一配置源 `src/config.py`。
> **两条全局硬规则**（team-lead 拍板，接口层兜）：
> ① 界面任何位置不出现 `s1` / `s2` / `ρ` / `N` / 任何百分比——分数只进 decisions 台账。
> ② 所有阈值从接口读，JS 不许写死。
> 载体：FastAPI 自带页面，`127.0.0.1:8765`，Safari 固定标签页。launchd 拉起 daemon 时顺带 `open`。

---

## 1. 载体选型

选**本地网页**。不选另外三个：

- **菜单栏应用当界面**：NSMenu 塞不进「播放器 + 3 句文本 + 一个下拉」。用 rumps 手搓 NSView，成本是网页两倍，还更难看。
- **Electron**：150MB 包 + 签名 + 公证，光公证吃掉一天，为 4 个按钮不值。
- **纯文件夹 + markdown**：确认动作没地方落，用户只能手改 md 再跑命令——他看代码，但不写命令。

菜单栏只留 30 行哨兵：发通知、点通知开 URL、显示待核对数。它不是界面。

> 声纹向量、原型、decisions 在 `~/.voiceprint/db/`，**不在 OneDrive**（生物识别信息不进同步盘，合规要求）。界面上任何「打开位置」只能指向 md，不能指向库。

## 2. 确认页 `/r/<recording_id>`

```
2026-10-28 讨论 回款流程.opus
音频 25 分 50 秒 · 2 个说话人 · 还剩 2 个没核对        另外 2 段也按此更新
●○                                   1 / 2
```

- 时长**必须**首行展示——发现半截文件的唯一人工线索。
- 用「没核对」不用「没确认」：稿子已经在了（`ready` 状态就有 md），他只是没盖章。
- 四个圆点可点跳转。

卡片，一屏一张：

```
说话人 A · 说得最多 · 23 分 49 秒（92%）

  ▶ 连听 15 秒
  ├ 0:12   3:41   8:07

  这是谁？
  这段里断断续续地像曹晓雨，我不敢定

  [ 就按 曹晓雨 记（我确认） ]
  [ 不是，选人 ]  [ 新人 ]
```

### 2.1 音频是主交互（数字退场后升级为硬约束）

- 3 段各 5 秒（`CLIP_SEC`/`CLIP_N`），按时间顺序拼 15 秒，段间 0.25 秒静音。主按钮一次播完，下面 3 个时间点可单独重听。
- **播放按钮占卡片高度三分之一以上**，带可见进度条。数字全禁之后，听是唯一判据；如果播放还要找一下才点得到，这张卡就是废的。
- **不做自动播放。** 他多半在办公室，进页面突然外放一次，之后就再也不敢开着这个页面——为了省一次点击，赔掉整个工具的信任。折中：记住上次的播放状态，如果他上次是静音/耳机的，则进卡自动播；否则大按钮 + 空格键播放。
- 段的选择由后端定：该簇**能量最高的 3 段**，取段内最高 RMS 的 5 秒。不要随机——随机会取到静音或串音段，听起来像换了个人，比不放更糟。
- 不用连续 15 秒：最长段可能上百秒且混着抢话，单段播会认错人。
- `再听一段` 需后端支持 `exclude`（排除已播过的段），否则重放同一段，用户会以为坏了。**簇没有未播段时按钮置灰**，文案 `只有这 12 秒，没法再听了`——这里的秒数是**实际片段时长，他可核实**，可以写。
- 文件落 `~/Library/Caches/voiceprint/<rec_id>/`，前端不拼文件系统路径，只吃 `/media/...`。

### 2.2 灰字：按 reason 选文案，一个数字都没有

**这条改变了原设计。** 我原来主张在两个分支显示 `0.41 / 0.44`，team-lead 否了——一旦出现 `0.50 却出卡`，用户会拿它对照「0.44 才敢认」，然后**连本来正确的卡一起不信**。他说得对：数字是他会误用、也核实不了的东西。所以解释「为什么来问你」的责任，全部转移到 reason 文案上。

| 分支 | 条件 | 灰字 | 主按钮 |
|---|---|---|---|
| 灰区（主力） | `T_ASK ≤ s1 < T_AUTO` | `听着像曹晓雨，但把握不够` | `是 曹晓雨` |
| 证据不足 | `s1 ≥ T_AUTO` 但 margin / ρ 未过 | `这段里断断续续地像曹晓雨，我不敢定` | `就按 曹晓雨 记（我确认）` |
| 新人 | `s1 < T_ASK` 且 `win_pass_rate ≥ 0.4` | `库里没有这个人，最像的也不像` | 候选列表为空：`新建一个名字` / `一次性的人` / `先留空` |
| 太短 | `reason=too_short` | `这段太短，先不认人` | 仅 `不是，选人` / `先留空` |
| 太吵 | `reason=noisy` | `声音太小或太远，这段没敢认` | 同上 |
| 抢话 | `is_overlap` | `这段像几个人在抢话，分段本身就不准` + `听 8:07 那段` | 同上 + `只出稿，不认人` |

- **`reason` 现在是载荷**：禁了数字，卡片能不能自圆其说全看 reason 准不准。少一个 reason 分支，就会出现一张「说不出为什么问」的卡——那比显示数字更糟。
- **多支同时成立时按固定优先级取一支**，别让枚举随机命中：
  `isolation_broken > 抢话 > 太吵/太小 > 断断续续 > 灰区 > 新人 > 太短`
  前几支是在说「这卡问了也没用」，后面的才是「我需要你帮我定」。先说不值得答的，再问要答的。
- **`isolation_broken` 不是卡片，是页面黄条。** 单簇占比 > 70% 且簇数 ≥ 3，出问题的是整段录音，不是某一簇——挂成簇级卡片会让他在错误的层级上做判断。那个簇降级成一行只读文字（`这段我可能分错了，暂不问你`），不给任何命名按钮；黄条写 `这段录音有 18 分钟被归成了同一个人，可能分错了`。
- **兜底支不给「是 X」**。`就按 X 记（我确认）` 是**用户在断言**，`是 X` 是**系统在问**。系统自己没把握时装一个「是」，等于把犹豫包装成结论。
- **`win_pass_rate < 0.4` 的簇不出卡**：那是真的录糊了，出卡只会让他硬猜。md 里标 `（声音太小或太远，没敢认）`。

> **门槛的两个说法是同一个数，别被单位绕进去。** 门槛判的是「有效语音」，即 `N_total × HOP`，`HOP = 1.0s`，所以「60 个窗」和「60 秒有效语音」等值——出卡 30、静默落名 60。
> 真正要防的是把它和**簇时长 `seconds`** 混用：一个 200 秒的簇，噪声大时有效语音可能只有 35 秒，会被判成「太短」。所以：
> - 接口给 `eff_sec`（有效语音秒数）**和** `duration_s`（簇总时长）两个字段，名字必须不同。
> - 卡片上「说得最多 · 18 分 20 秒」用 `duration_s`；门槛判断用 `eff_sec`；**文案里永远不写门槛数字**。
> - 例外：试听片段的实际时长可以写（`只有这 12 秒`），因为点开就能核实。
> - **`eff_sec` 同样不可写入文案。** 它由 `N_total × HOP` 推出，而 `N_total` 受 `cap=1200` 截断（80 分钟的簇最多算到 1200 秒，实际 4800 秒），用户听到的时长会和它对不上。**文案里唯一允许出现的秒数，是 `clips` 的实际可播时长**，由后端算好、前端只展示。

### 2.3 三选一

- `是 X`：仅灰区支出现。
- `不是，选人`：展开库里人名。**第一行就是 `都不认识，先留空`，不藏在末尾。** 新人卡现在可能占六成录音，留空是正常选项不是失败——藏起来会逼他从列表里随便挑一个最像的。
- `新人`：输入框 + 两个**等权**单选行（同样大小、同样颜色、都不预选）。

```
名字 [__________]

( ) 记住他，以后自动认
( ) 只用这一次，下次还会问你        ← 不选完，「确定」不可点
```

**不写「不再问你」。** 跨设备分数整体下移是已知问题：下次手机录到同一个人，系统照样会问。一句两周内必然被证伪的承诺，会让整页失信。

### 2.4 点完立即生效

不设「全部确认」。点一下 → `POST /decisions` → 翻下一簇 → 右下角 6 秒 toast `已标记 说话人 A = 曹晓雨 · 撤销`。md 同步重渲染。

一屏处理 **1 个簇**：音频要占位置，四个播放器挤一屏每个都太小。实测 2~4 簇。

### 2.5 回填提示

勾了「记住他」，其他待核对录音里同一个人立刻被认出来。**不能静默**——静默等于这次入库没发生过，下次还问同一个人。

提示挂在**当前确认页顶栏**（他正站在这页，列表在别的页面看不到）：小字、不可点、5 秒淡出。不出卡片、不弹 toast、不打断「核对下一张」的心流。

**硬规则：只回填没有 `user_verdict` 的簇。** 他签过字的东西不能被后来的入库动作改掉。宁可少认一段，不可改他已定的事。

## 3. 三个状态

| 界面名 | 后台 | 他看到的 |
|---|---|---|
| 处理中 | `processing` | 分段进度，见下 |
| 已出稿 · 待核对 | `ready` | 稿子已可读，卡片待盖章 |
| 已完成 | `confirmed` | 全部盖过章 |

**关键改变：`render` 完成就写 md，确认不是出稿前提。** 稿子始终存在，确认只是盖个章。他哪天不处理，那天也不缺任何东西。

处理中三段文案：

| 阶段 | 主文案 | 副文案 |
|---|---|---|
| waiting_stable | `等文件传完` | `OneDrive 还在下载，传完再动，否则会分析到一半` |
| diarize | `正在分离说话人` | `25 分钟音频，大约 1 分钟` |
| score | `正在比对声纹` | `和库里 2 个人比对` |

第一阶段必须解释：可能卡 60 秒以上，不解释他以为挂了。超预估 2 倍只写 `比预计慢，还在跑`。**此阶段不给任何半成品人名。**

## 4. 通知

只在「进入 ready 且有未核对簇」时发，一条录音一条。

- 标题 `2 个说话人待核对`，正文 `14:17 讨论 回款流程 · 25 分钟`，点击直达 `/r/<id>`
- 不发的：全部自动落名的、处理中。失败单独一条 `处理失败`

一天不处理：不催。md 照常按 `未知A/未知B` 出。次日 18:00 若待核对 ≥3 份，发一条汇总，仅此一次。

## 5. 异常态

**疑似分离失败**（最大簇 > 60% 且总时长 > 40 分钟）顶部黄条：

```
⚠ 这段录音的分离可能出错了：一个人占了 92% 的时间。
  长录音常见这个毛病。可以指定人数重跑。
  [ 自动 ] [ 2 人 ] [ 3 人 ] [ 4 人 ]        [ 重跑 ]
```

把比例写出来——这是他能自己核实的（听一下是不是一个人说了全场）。**比例是比例，不是分数，不在禁令范围内。** 不做弹窗，会挡住内容。

**抢话**：见 §2.2。告诉他「这张卡问得没道理」，别硬猜。

**处理失败**：`处理失败：转码出错` + `[ 重试 ]` + `[ 查看日志 ]`。中间产物保留，重试幂等。

**文件改名**：行右侧 `文件已改名 · 3 分钟前`，点开显示新旧名。不弹窗不通知。

**认错了没人发现**：三条便宜兜底——(a) md 首行 `> 带斜体的名字是我自动认的，没经你核对`；(b) 完成页保留 `重新打开核对`；(c) 名字不烧进 md，`segs + decisions` 留着。c 最重要。

## 6. 撤销：两个入口，权限不同

用户点「新人 + 记住他」→ 向量进库 → 点撤销。只改文字的话，库里那条生物特征还在，他以为撤了。这是隐私问题。

采用**立即写库 + 按 `source_id` 精确删**（不用延迟 6 秒：延迟窗口和 arch 的「<1 秒跨录音全量回填」重叠，撤销后人名回来了，但那几份录音是用一条后来被否认的原型算的，成了幽灵）。

**撤销 = 删 source → bump `proto_version` → 重算 L2 → 把所有受影响的 md 重渲染。** 最后一步不能漏：只重算不进文件，他翻到的还是幽灵名字。

| 入口 | 时限 | 能做什么 |
|---|---|---|
| toast `撤销` | 6 秒内 | 可删 source，连库一起回滚 |
| 铅笔图标 | 任何时候 | **默认只改判，不动库** |

铅笔改判时，若该簇有 `source_id`，多给一行**默认不勾**的：

```
☐ 顺便删掉库里的「张三」（删了下次还得重新认）
```

不勾 = 只改这份稿子（下次遇到他还会自动认成张三，可接受）；勾了才删。默认安全。

**铅笔不给自由输入**，只能改判为库里已有的人或「未知」。要新建名字必须走「新人」——那条路会显式问入库。否则「张三」改成「张三（销售部）」这种纯改名会和库里记录对不上，而他不知道后果。

## 7. md 渲染规则（强制，不靠用户记）

| 写法 | 含义 |
|---|---|
| `**张三**` | 人盖过章 |
| `*张三*` | 自动落名，没核对 |
| `**未知A**` | 没核对过 |

- 首行固定：`> 带斜体的名字是自动认的，没经你核对。`
- 未定簇按**发言时长降序**编 `未知A/未知B`。都叫「未知」分不清是同一人还是两人。
- 簇判定表标注：`one_off` → `（一次性，未入库）`；没参与判定 → `（这段太短，没认人）` / `（声音太小或太远，没敢认）`。**只放判定表，不逐行加括号**——20 秒插话十几行，逐行加会把正文压垮。
- 存在未定簇时文件名带 `unconfirmed`。

## 8. 分支判定表（给实现，一张图看完）

```
total < 4s 或 eff_sec < 30              → 不出卡，md 标 too_short
win_pass_rate < 0.4                     → 不出卡，md 标 noisy（真录糊了）
s1 < T_ASK 且 win_pass_rate ≥ 0.4       → 出卡「新人」reason=few_match
T_ASK ≤ s1 < T_AUTO                     → 出卡「灰区」（主力）
s1 ≥ T_AUTO 但 margin / ρ 未过          → 出卡「证据不足」
s1 ≥ T_AUTO 且 margin / ρ 都过 且 eff ≥ 60s  → 静默落名，不出卡
```

`is_overlap` 可叠加在任一支出卡上加警示。

**新人卡不设「每场最多 1 张」。** 两个新人的会议很常见（面试官 + 候选人、带两个新客户的拜访），限 1 张等于让第二个新人沉进 md 的 `未知B`、永远无人认领——正是这套系统要修的病。用统一次序控制量：**出卡顺序按 `seconds` 降序**。

**折叠规则只作用在列表页**：列表一屏最多 3 行，其余折成 `还有 N 个没定`。**确认页仍是一屏一簇**——音频和 3 句文本需要空间，三张卡挤一屏会让每个播放器都变小。这两条不冲突，是两个页面各自的密度。

> **折叠 ≠ 丢弃。** 折叠必须能展开，展开后每一簇仍可正常认领。区别是：折叠可恢复，丢弃不可恢复。前者控密度，后者毁需求——名单里没有入口的簇，等于变成了 md 里一个永远无人认领的 `未知C`。

## 9. 需要接口补的

1. `is_overlap: bool`（同区间多 speaker 时长占比 > 15%）。没有它，「抢话」文案永远不出现。
2. `win_pass_rate`（原始 float，前端只用来选分支，不显示）。这是区分「录糊了」和「库里没这人」的唯一依据。
3. `POST /decisions` 返回 `backfilled: {count, rec_ids}`，供顶栏那行小字。
4. 拼接函数支持 `offset` / `exclude`，并返回「是否还有没播过的段」。
5. `/health` 或配置接口吐 `T_AUTO / T_ASK / MARGIN / RHO_MIN / min_eff_sec_ask(30) / min_eff_sec_auto(60)`。**单位写进字段名**，且必须是「有效语音秒」不是「簇时长」。
6. `eff_sec`（有效语音秒）与 `duration_s`（簇总时长）**必须是两个字段**。混用会导致「说了 18 分钟却被判太短」——这不是显示 bug，是判定 bug。
7. `second` / `second_name` 按全局禁令已从响应移除；DB 侧保留（台账要能复盘），只是不进 API。
8. `reason` 必须是**枚举，不许自由文本**，前端按枚举查表。七支缺一不可：`isolation_broken` / `low_margin` / `low_rho` / `too_short` / `noisy` / `few_evidence` / `few_match`。缺一支就是一张说不出理由的卡。
9. 多支 reason 同时成立时，**由后端按固定优先级只返回一支**（`isolation_broken > low_rho/抢话 > noisy > few_evidence > low_margin > few_match > too_short`）。让前端排优先级，等于把产品语义散到展示层。
10. 出卡列表按 `duration_s` 降序返回，前端不排序。
11. 验收项：界面任何「打开位置 / 在 Finder 中显示」只能指向 md，**不能指向 `~/.voiceprint/db/`**。

## 10. 成本与取舍

界面约 300 行 HTML + 200 行 JS。真正贵的是 daemon 的胶水（监听、队列、崩溃恢复）。

砍掉：波形图、时间轴、逐句编辑器、逐句置信度上色、批量确认、联系人管理独立页、深色模式、通知角标、倍速播放。

最贵的两处及砍法：**任意时间轴播放** → 后端预切 3 个 wav，前端一个 `<audio>`；**候选 top3 + 排序** → 只给 1 个最可能 + 全量人员列表。
