## 0. 一句话

录音落进 `~/OneDrive/数据库/录音/` 后全自动出带人名的逐句稿；**没把握的、库外的人，才来问你**。

## 1. 判定序列（终版，按序短路）

```
1. N_total < 30                                       → few_evidence（不出卡，进 md/台账）
2. 塌陷：n_clusters ≥ 3 ∧ max_cluster_share > 0.70     → 录音级：页面黄条 + md 预警，该簇只读
3. 允许静默？N_total ≥ 60 ∧ s1 ≥ 0.44 ∧ margin ≥ 0.05 ∧ ρ ≥ 0.70
                                                      → 静默落名（斜体）
4. s1 ≥ 0.36 ∧ 出卡门槛达标                            → 疑似卡（不看 win_pass_rate）
5. s1 < 0.36 ∧ win_pass_rate ≥ 0.40 ∧ 出卡门槛达标      → 新人卡（不看分数）
6. s1 < 0.36 ∧ win_pass_rate < 0.40                   → 不出卡，reason=noisy
7. 其余                                               → 静默标「说话人N」
```

**`win_pass_rate` 只拦新人档，绝不拦疑似卡。**
第 4 步只看分数：疑似卡的依据是「像不像人」，不是「信号干不干净」。一张 `s1=0.40` 但 `win_pass_rate=0.2` 的簇**必须出卡**，文案走 `noisy`（那段确实糊）——不能因为说了「声音小」就不出卡，那会把最该问人的一批悄悄吞掉。

**出卡门槛**：`N_total ≥ 30` ∧ `seconds ≥ min(60, dur_total × 0.3)`（后者只对出卡生效，不约束静默）。

**reason 码表（最终冻结 · 2026-10-28，命名争议用别名表终结）**

```python
ALIAS = {"close_call": "low_margin", "few_match": "unknown_person", "overlap_speech": "mixed"}
```

链路按「我们的把握程度」短路，命中即返回：

| 序 | 码 | 触发 | 卡面 | 按钮 |
|---|---|---|---|---|
| 1 | `mixed` | ρ2 ≥ 0.25 | 这段像几个人在抢话，去听一下 | 听 / 选人 |
| 2 | `mixed_weak` | 0.10 ≤ ρ2 < 0.25 | 断断续续，可能还是抢话 | 听 / 选人 |
| 3 | `noisy` | win_pass_rate < 0.40 | 声音太小或太远，这段没敢认 | 听 / 选人 |
| 4 | `low_margin` | s1 ≥ 0.44 ∧ margin < 0.05 | 像两个人，分不出 | **两选一** |
| 5 | `few_windows` | s1 ≥ 0.44 ∧ 30 ≤ N < 60 | 听起来是他，但只听到 **42 秒** | 只给「就按 X 记（我确认）」 |
| 6 | `low_rho` | ρ 不达标 | 这段说得不太一致，拿不准 | 选人 |
| 7 | `gray_zone` | 0.36 ≤ s1 < 0.44 ∧ ρ 达标 | 听着像 **曹晓雨**，但把握不够 | **带名字的一键确认** |
| 8 | `unknown_person` | s1 < 0.36 ∧ win_pass_rate ≥ 0.40 | 库里没有这个人？ | 新建 / 一次性（不入库）/ 先留着 |

不进链：`too_short`（md 标签）、`few_evidence`（内部信号）、`same_person`（渲染标记，库≥5 人启用）、`isolation_broken`（录音级 `warnings[]`）。

**三条硬规矩**
1. **`few_windows` 的秒数是全篇唯一允许出现的数字**——有效语音 < 60 秒时 `CAP=1200` 咬不到，数字不会被截断污染、用户能自行核实。孤例，不得作为先例扩张。
2. **`low_rho` 一码一义**，只写「说得不太一致」。接口已把 `s1` 置 null，前端按分数分文案在物理上做不到，别要求它。
3. **`gray_zone` 必须由后端产出**，不能只在前端写文案。库小阶段它是占比最大的一支，漏了这批卡全部说错话。

**静默档的两个硬门槛（2026-10-28 实测追加，优先级最高）**

实测事故：面试录音 3 个互斥簇全部被判成同一个人，s1=0.568/0.614/0.581、margin 0.30+、ρ 0.99+ —— 四条静默条件全部通过。原因是该人的原型只有 42 个窗、单一来源，**编码的是信道而不是人**；同一人换一段录音立刻掉到 0.345。

```
静默落名额外与条件：
  proto_n  ≥ N_PROTO_MIN  = 100     # 原型窗数不足 → 只能进疑似
  source_n ≥ N_SOURCE_MIN = 2       # 独立录音来源不足 → 只能进疑似
  unverified == False               # 来源≥2 时跑 leave-one-source-out，中位数 < T_AUTO 则永久疑似
```

后果要说清：**曹晓雨 140 窗、金雪竹 209 窗，但都只有 1 个来源，他们同样被挡在静默档外。** 在第二段来源攒到之前，静默档事实上为空，全部走疑似卡。

这不是退步——这暴露了「静默落名」本来就没有统计基础。宁可全问，也不能靠一个被信道污染的原型静默署名。

**排序**：疑似/新人卡按 `seconds` 降序。超出 3 张折叠为「还有 N 个没定」，**必须可展开认领**。

## 2. 常数（唯一来源：`src/config.py`）

| 键 | 值 | 说明 |
|---|---|---|
| `T_AUTO` | 0.44 | 静默落名门槛 |
| `T_ASK` | 0.36 | 提问下沿 |
| `MARGIN` | 0.05 | 次优差；库 <5 人时恒真，仅作保险 |
| `RHO_MIN` | 0.70 | 一致窗比例；**只降级不升级** |
| `N_MIN_ASK` | 30 | 出卡下限（窗）＝ 30 秒有效语音 |
| `N_MIN_AUTO` | 60 | 静默下限（窗）＝ 60 秒有效语音——**只防纯噪声，不保证正确性** |
| `WIN_PASS_MIN` | 0.40 | 新人卡信号质量下限 |
| `CAP` | 1200 | `windows_of` 截断上限 |
| `NEW_PER_REC_MAX` | 3 | 新人卡张数上限 |
| `NEW_MIN_SEC` | 60 | 新人簇最短时长 |

⚠️ **必读警示（写进 config 注释）**
> 即使 80 个窗，±2SE≈0.039 也大于 `T_AUTO` 与最近正例（0.456）之间的间隙 0.016。
> **统计上没有任何簇「够格」静默署名。** 静默档的本质是「用 T_AUTO 把可疑的推给人，接受残余错误率」，不是「窗够了就保正确」。

⚠️ `win_pass_rate = N_total / min(N_theory, CAP)`。分母必须封顶，否则 30~100 分钟的簇会被 cap 截断污染，判据在该区间失效。簇长 > CAP 时 `win_pass_rate ≡ 1.0`，无诊断意义。

⚠️ `win_pass_rate` 测不到**分离塌陷**（塌陷时窗能量全够，它接近常态 0.74）。塌陷只能靠 `max_cluster_share` 判。

**已删除**：`0.70 / 0.08`（质心分支遗留）、`0.45`（历史手传）、`0.40`（拆成 0.44/0.36）、`N_MIN_HARD=15`、短录音动态放宽公式、`--threshold` CLI 参数。

## 3. 字段命名（写进 config 注释，不许自创）

```
N_theory   = floor(seconds) − 1      # 理论窗数，只做展示与自检
N_total    = windows_of 返回长度      # 能量过滤 + cap 之后，ρ 的分母
N_valid    = best_sim ≥ T_ASK 的窗数  # 只进台账做诊断，不参与任何判定
eff_sec    = N_total × HOP            # HOP=1.0s，故 30/60 窗 ≡ 30/60 秒有效语音
duration_s = 簇内各段时长之和          # 含停顿；只用于展示「说得最多 · 18 分 20 秒」
```

**判定只用 `N_total`。** `N_valid` 永远不参与判定。

⚠️ **`eff_sec ≠ duration_s`**，这是最容易混的一处：一个时长 200 秒的簇，有效语音可能只有 35 秒（大半是停顿）。
- 门槛看 `eff_sec`
- 卡片统计行看 `duration_s`
- 两者都不许写进「这段太短」之类的话里

**窗与秒是同一个量**：`HOP = 1.0s`，所以「60 个窗」和「60 秒有效语音」是同一道线的两种说法，不存在单位换算争议。争议只发生在把 `eff_sec` 当成 `duration_s` 的时候。

## 4. 卡片

**四个元素**：播放按钮（禁数字后唯一判据）、该簇 ≤3 句转写（无转写时显式写「这段没有转写稿，只能听」）、一句 reason（不带任何数字）、三个按钮。

**播放器规格**（不做自动播放）：
- 按钮高度 ≥ 卡片 1/3，带可见进度条，空格键可播
- **默认不播**；只有用户**主动点过播放**的后续访问才自动播（记住的是「他愿意出声」这个决定，不是「上次没静音」）
- 理由：他多半在办公室，进页面突然外放同事的声音，一次之后就会关音量或不再打开这个页面。**省一次点击赔掉整个工具，不划算。**

**按钮**：`是 X` / `不是，选人` /（新人卡）`新人入库`。
`不是，选人` 展开列表**第一行**是 `都不认识，先留空`。

**禁用**：界面任何位置不出现 `s1 / s2 / ρ / N`，包括调试灰字。接口层返 `null`，不靠前端自律。

**文案里唯一允许出现的秒数 = `clips` 的实际可播时长**（他点开就能核实）。
`eff_sec` / `duration_s` / `N_total` 都不进时长描述。`duration_s` 只用于卡片统计行（`说得最多 · 18 分 20 秒`）。

**reason 枚举（接口码，8 支，后端按序短路只返一支）**

> ⚠️ **定名冻结，永不再改。** 本轮曾出现四套名字（我起的 `overlap_speech/close_call/unknown_person`、team-lead 的、arch 已提交的、ux 的并集）。
> **名字没有好坏，反复改才有成本**：改一个名要动代码 + 文档 + 接口三处，改回来还要再动一遍。
> 规则：以后谁改已有码名，谁负责同步三处；且必须先问「已实装的是什么」，再定名。

| 码 | 触发 | 卡型 | 文案 |
|---|---|---|---|
| `mixed` | `rho2 ≥ 0.30` | 疑似 | 这段像几个人在抢话，分段本身就不准 |
| `mixed_weak` | `0.15 ≤ rho2 < 0.30` | 疑似 | 这段可能有人在插话 |
| `noisy` | 能量低 / 太远 | 疑似 | 声音太小或太远，这段没敢认 |
| `close_call` | `s1 ≥ 0.44 ∧ margin < 0.05` | 疑似 | X 和 Y 都像，听得出是哪个吗 |
| `few_windows` | `s1 ≥ 0.44 ∧ margin ≥ 0.05 ∧ ρ ≥ 0.70 ∧ 30 ≤ N < 60` | 疑似 | 这段总共 42 秒，太短了不敢定 |
| `low_rho` | `ρ < 0.70 ∧ rho2 < 0.15` | 疑似 | 断断续续地像 X，我不敢定 |
| `gray_zone` | `0.36 ≤ s1 < 0.44` | 疑似 | 听着像 X，但把握不够 |
| `no_match` | `s1 < 0.36` ∧ 新人档 | 新人 | 库里没有这个人，最像的也不像 |

**优先级（按序短路）**：
`mixed > mixed_weak > noisy > close_call > few_windows > low_rho > gray_zone > no_match`

排序依据是**「我们有多具体」降序，不是 s1 高低**：
- 前两支「这卡问了也没用」
- `noisy` 同理
- `close_call` 已缩到两个人，最可操作
- `few_windows` 分数够、只是听得少，把握高于后面三支
- `low_rho` / `gray_zone` 依次更模糊
- `no_match` 只知道「不在库里」

**文案必须同族**：`mixed` / `mixed_weak` 都属「抢话」族，`low_rho` 属「不像他」族。
否则用户在 `rho2` 边界附近会看到两种完全不同的诊断（今天「有人抢话」、明天「断断续续」）——**这才是真正让人怀疑系统的东西，与码名无关，与文案分族有关**。

⚠️ **命名与边界红线**：
- `is_overlap` 是**录音级字段**（bool），不进 reason。reason 用 `mixed`。
- 非卡片标签（只进 md 与台账）：`few_evidence`（`N_total < 30`）、`too_short`（出卡门槛不达标）。
- **`few_windows`（30 ≤ N < 60，出卡）与 `too_short`（N < 30，不出卡）不许合并**——都在说「短」，一个在卡上、一个在 md 里。
- `no_match` 不叫 `new_person`：不能预设他是新人，只能说他不在库里。

**唯一的数字例外**：`few_windows` 的 `这段总共 42 秒`。
- 理由：这一支的前提是有效语音 < 60 秒，`CAP=1200` 在 20 分钟以上才咬人，所以此处的秒数**不会被截断污染**，用户可以自己核实。
- 主语必须是「这段」（他核实的是这段多长），**不能是「只听到」**（那暗示系统只处理了 42 秒，且和卡片实际播的 15 秒冲突）。
- 此为孤例，**不得被当作先例**扩张到其他支。

**`close_call` 要特殊处理**：这一格知道的是「就在这两个人里」，比「像 X 但不确定」信息量大得多。卡片应直接给 `是 X` / `是 Y` 两个一键选项，别让他从全库选。
（库 <5 人时 `margin` 恒真，此支不触发；库长大后会开始出现，届时若随机落到别的支，就等于把最有把握的一张卡说成最没把握。）

**新人卡的特殊限制**：不给「是 X」；不给数字；只描述可核实的证据（段数/时长）。
系统自己没把握时装一个「是」，等于把犹豫包装成结论。

**文案禁则**：不出现催促词（`待办`/`请尽快`/`还有 N 项未完成`）。只能陈述 `还剩 2 个没定`——他一天不处理零损失，没有理由催。

## 4b. `isolation_broken` 是录音级，不是簇级

单簇占比 > 70% 且簇数 ≥ 3 时，出问题的是**整段录音**的分离结果，不是某一簇。

- 表现：页面顶部黄条 `这段录音有 18 分钟被归成了同一个人，可能分错了`
- 该簇：降级为一行**只读文字**，不给任何按钮
- **黄条上不放「重跑」按钮**。重跑分离要指定人数（2/3/4），而塌陷的成因恰恰是「聚类塌了」——让他填人数，等于在最没信息的时候做技术含量最高的决定。黄条只告知，附一句 `可以在 md 头部看到哪些分钟被合并了`，处理留到人工
- **绝不挂成簇级卡片**——那会让他以为「跳过这张就没事」，然后信任剩下那些其实同样不可信的卡

`isolation_broken` **不是 reason、不进任何卡片**。把它做成簇级 reason，等于让他在「这一簇要不要认」的层级上回答「整段可不可信」——层级错了，答案必错。

**时长只能来自 `clips` 实测**，不许由 `N_total × HOP` 反推（受 cap 污染、且与用户听到的不一致）。

## 5. 入库与撤销

- 入库二选一，**不设默认值**，视觉权重相等：`记住他，以后自动认` / `只用这一次，下次还会问你`。
  同一人后续提示为 `（一次性，未入库）`。
- **立即写库**，不延迟。撤销 = `删 source → bump proto_version → 重算 L2 → 重渲染所有受影响的 md`。
  最后一步不可省：只重算不落文件，用户翻到的还是幽灵名字。
- 两个入口权限不同：
  - toast 撤销（6 秒内）：可**删 source**（连库回滚）
  - 铅笔（任何时候）：**只改名字，不许碰库**；只能选库里已有的人或「未知」，**禁止自由输入**
  - 铅笔改判已入库者时，给一行默认不勾的 `☐ 顺便删掉库里的「张三」`
- 自由输入的禁令理由（文档原话）：**不是显示对不上，是制造一个永远认不出的新身份。**

## 6. 存储

| 内容 | 位置 | 可重建 |
|---|---|---|
| `.说话人.md` | OneDrive 录音目录 | 是（渲染产物，人名结果的副本） |
| `decisions.jsonl` | `~/.voiceprint/` | **否**（唯一必须持久到字节的东西） |
| `state.json` | `~/.voiceprint/` | 是（扫目录 + 重算指纹） |
| 声纹库 / 原型 / 切片 | `~/.voiceprint/db/` | **否**（需切片固化） |

- **绝不进 OneDrive**：`decisions.jsonl`、声纹向量、原型缓存、state.json。
- **注册时把该簇音频切片另存** `~/.voiceprint/db/voices/<name>/`，切断对 OneDrive 原文件名的依赖。
  该用户有按规则批量改名录音的习惯（`录音重命名记录-20261027.md` 为证），一次改名就会让原型重建静默失败。
- `decisions.jsonl`：append-only，`seq` 分配在写锁内 `max(seq)+1`；撤销 = append `{type:"revoke", revokes:<id>}`；
  **revoke 后不回退到更早的 assign**（用户否认过的人不能被他自己的历史确认复活）。
- md 里写入 decisions 版本号，读时版本不一致自动重渲染。

## 7. md 渲染

- 自动判的**斜体**，人确认的**粗体**，首行注明规则。
  **斜体不是装饰，是静默署名的前提条件**——去掉它就是让错误隐形。
- 未定簇按发言时长降序编 `未知A / 未知B`。
- 塌陷预警带具体数字：`这段录音有 80 分钟被归为同一个人`。
- 每段说话人块后附不可见锚点 `<!--ev:<event_id>-->`，用户手改名字后回写时解析，捞回「静默判错」样本。
- 段落级别加 `（这段太短，没认人）` **只在判定表里标**，正文不加——逐行加括号会压垮正文。
- **`same_person`（库 <5 人时不启用）的只读兜底**：md 里补一行 `这段可能和别的簇是同一个人，我没分开`。
  理由不是体验，是**诚实**——他看到「一个明显像张彤的簇却没有名字」，不解释会以为系统坏了；而实际是我们看到了这个可能性、不敢下结论。
  措辞必须弱，且把责任放在我们这边。只进 md，不进卡片、不给按钮、不影响任何指标。

## 8. 指标（终版）

| 层 | 指标 | 目标 | 不达标含义 |
|---|---|---|---|
| 前置 | 推送后 24h 打开确认页 | ≥50% | **打扰方式错**（通知文案/时机） |
| 主 | 打开后 B 类占比 | ≤40% | **产品形态错** |
| 主 | 每个新说话人的平均点击 | ≤3（理想 2） | 流程有冗余 |

**A/B 定义**
- A 类（有效）：`是 X` 或 `新人入库`——问对了，且买到资产
- B 类（空转）：`先留空` 或直接关页——用户自己也不知道，零收益

**两级判据**（不许读成一级）
- 单周 B>40% → 查机制（门槛/噪声/提问过密），**不判死刑**
- 连续 4 周 B>40% 且无改善 → 判形态错

**已作废**：静默率 ≥70%、≤4/≤16/≤8 次/10h 梯度表、P90 ≤ 时长/10。
理由：这些数的分母含「录音时长/条数」，由业务量决定而非产品。见 §10。

**性能**：任意长度 P90 ≤ 6 分钟；≥60min 长会 ≤15 分钟。分流 `VP_SEG_MIN_SEC=1500`（<25min 单段直跑）。

## 9. 已知限制（写进文档，别当 bug 修）

1. 统计上没有任何簇够格静默（见 §2 警示），静默档带残余错误率。
2. `win_pass_rate` 测不到分离塌陷，只能靠 `max_cluster_share`。
3. 入库后回填过的其他录音，撤销时不会自动还原（`decided_by_source` 已预留字段，还原逻辑留 v2）。
4. 跨设备分数整体下移未量化，靠阈值硬挡。
5. 重叠说话/抢话是分割模型上限，只能识别、不能修。
6. 本地不含 ASR：无 `.md` 的 m4a/opus 只能产出「谁在说」，产不出逐句稿。
7. 短簇（<出卡门槛）静默标「说话人N」，无认领入口；v2 提供 md 内点「说话人N」补名。

## 10. 方法论（防同类错误再犯）

> 验收指标里凡是分母含「录音时长」或「录音条数」的绝对数，一律先问：
> **这个数由业务量决定，还是由产品决定？** 由业务决定的，不能当验收标准。

本轮据此推翻过两个目标（`≤4 次/10h`、`≤16 次/10h`），两次都错在「假设一段录音最多一个新人」——而销售一天见三拨客户是常态。

同类提醒：
- **碰巧对了**是最危险的通过方式。判据在错误机制下得到正确结果（如 `cap` 截断冒充塌陷检测），测试会过、真实场景会漏。
- **两个门槛并用**会让边界随机落点。同一件事只允许一个门槛。
